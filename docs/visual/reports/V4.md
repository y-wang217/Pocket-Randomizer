# V4 report: run summary as payoff

Stage V4 of `docs/spec/gymrun-visual-identity-plan.md`, run unattended under
`docs/visual/OVERNIGHT.md`. Every checkpoint green; guarded screens equal the
baseline to the pixel; no file under `data/` changed and the data digest is
identical to the baseline.

## Morning decisions

1. **Sprites need the network.** They resolve through `@pkmn/img`'s adaptable
   entry to Showdown's Gen 5 static set, and this sandbox cannot reach that
   host, so every screenshot here shows the sprite's box empty (the image
   hides itself on error, so no broken-image icon). On a phone they draw. If
   Gen 5 is the wrong set, `ui/sprites.ts` is one `gen` option.
2. **"New seed" stayed, hollow.** The plan names two actions, rematch and copy
   seed. The summary has had a third since Stage 1, and the seed bar it would
   otherwise fall back to is hidden on a phone during a run, so it stays as
   a second hollow button. Delete one line in `screens/summary.ts` if two is
   the number.
3. **The result screen's two decision points are measured in the two shapes
   the app renders**, cards without capture and capture without cards, since
   `playRun` asks the two questions in sequence and the screen never shows
   both. Rendered together as a worst case (`screen=result-both` in the
   gallery), the capture lands at 1293 and cannot be above the fold on any
   phone; the prompt's "three-card offer with a capture present" is read as
   the run having both, each on its own render.
4. **The party rows on the result screen became the V2 slot row**, HP and PP
   as the slot's detail line, statuses as chips in the slot. That is what
   moved the capture's buttons from 872 to 742. The HP bar per member is
   gone from that screen; it is still on the map's party panel a tap later.

## V4.1 what the summary can read

From run state (`RunResult.state`): the outcome; the seed; the eight
segments with leader, type, locale offer and routes; the locale chosen per
segment (`localeChoices`, resolved through `routeAt`); every node visited
(`history`: kind, label, tier, opponent, turns, winner, HP after, casualties);
the final party (species, level, ability, gender, moves with PP, item, HP);
relics, backpack, currency. From the decision log (`RunResult.log`): every
decision by kind. Through `core/`'s existing readers: `gymsCleared`,
`causeOfDeath`, `offensiveCoverage`, `describeSpecCard`, `describeMove`,
`WHEEL_TYPES`.

What the design needs and where it comes from:

| design element | source | derived where |
|---|---|---|
| outcome word | `result.outcome` | copy in `ui/copy/summary.ts` |
| gyms cleared over eight | `gymsCleared(state)`, `GYMS.length` | as is |
| route: eight locale bands | `segments`, `localeChoices`, `routeAt` | `ui/` |
| route: one dot per node taken, gym larger | `history` | `ui/`; non-gym dots equal the log's `node` decisions, asserted |
| route: death point | `causeOfDeath` and the last visit | `ui/` |
| tier table | `gymsCleared` | copy and ranges in `ui/copy/summary.ts` |
| final party in slots with sprite, level, types, ability, moves, item | `party`, `describeSpecCard`, `describeMove`, `@pkmn/img` | `ui/` |
| coverage wheel | `offensiveCoverage(party)`, `WHEEL_TYPES` | `ui/`, read only |
| cause of death band | `causeOfDeath` | as is |

Nothing needed `core/`. Nothing was dropped.

## V4.2 layout and copy

`src/ui/copy/summary.ts`: `OUTCOME_WORDS` (VICTORY, FALLEN), five `TIER_ROWS`
(0–2, 3–4, 5–6, 7, 8) each with a range, one line of sentence-case copy and
a 12x12 inline glyph, and `tierRowFor`. `test/summary.test.ts` lands every
value 0 to 8 on exactly one row, checks the bold row in the DOM for a played
run, and asserts `dataDigest()` equals `docs/visual/baseline/data-digest.txt`.

## V4.3 data as decoration

- Route: `.route`, eight `.route__band` cells, each wearing `.locale--<id>`
  so V1's tokens colour it; `.route__band--unreached` for a segment never
  entered; `.route__dot` per visit, `--gym` larger, `--death` on a defeat's
  last dot. SMOKE24: 29 dots, 25 of them the 25 logged node decisions.
- Final party: `.summary__member` cards numbered by `slotNumber`, a sprite
  from `ui/sprites.ts`, level, type chips, the ability chip, the held item's
  icon, HP, and every move through the shared `moveCard`.
- Coverage: an 18-spoke SVG wheel in reading order, reached types filled,
  with a one-line legend naming them. No count, no score.
- Cause of death: `.summary__cause.strip`, the V2 band's surface as a static
  strip (`.strip` is shared with the confirm band's body); hidden and empty
  on a victory.
