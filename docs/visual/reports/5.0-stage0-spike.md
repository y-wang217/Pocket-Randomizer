## 1. Sprite coverage

**Recommended style: gen5 static** (`gen5/` front, `gen5-back/` back). It is what
the app already ships (`src/ui/sprites.ts`), and it is the only style that is uniform.

| | Count | gen5 front | gen5 back |
|---|---|---|---|
| Drawable species (`SPECIES_POOL` minus the 2 blacklisted) | 898 | 898 | 898 |
| Battle-only formes the sim can switch to mid-fight | 13 | 13 | 13 |

Every URL was checked with a HEAD request against the CDN, 5,937 in all. All
1,826 gen5 PNGs were downloaded: every one is 96x96, and front and back share a
baseline (median visible bottom edge at y=74).

Other styles, and why not:

- **gen5ani** mixes animated GIFs with silent PNG fallbacks: 132 fronts and 165 backs are static.
- **ani** is 3D renders at a varying canvas size, not pixel art.
- **dex** has no backs.

**Gaps and fallbacks:**

1. **A live bug, not a gap: 13 battle formes blank mid-fight.**
   - `sprites.ts` builds the id with `toId`, which drops the hyphen. It requests `mimikyubusted.png`; the file is `mimikyu-busted.png`.
   - The formes: Castform ×3, Cherrim-Sunshine, Darmanitan-Zen, Wishiwashi-School, Minior-Meteor, Mimikyu-Busted, Cramorant ×2, Eiscue-Noice, Morpeko-Hangry, Palafin-Hero.
   - All 26 real files exist. The fix is a 13-entry spriteid map.
   - Stage 0 writes no production code, so this is recorded and not fixed. It belongs in 5.0/2 or its own patch.
2. **89 gen 9 backs are mirrored fronts.** That is the 88 gen 9 species plus Palafin-Hero. They load at the right size and style.
   - No gen5-style true back exists on the CDN for any of them.
   - Recommendation: accept them.
3. **Any other 404:** keep today's fallback, a hidden 96x96 box (`visibility: hidden`). It holds the layout and keeps the beat animations running.
   - The spike's visible dashed box (`?missing=1`) is the same size and shows the alternative.
4. **Mini icons:** 911 of 911 have a real cell on the icon sheet.
   - The app's adaptable stub returns `num: 1` for every species, so building icons on it would draw Bulbasaur everywhere.
   - Icons need a generated num/icon table, in the manner of `ui/theme/itemIcons.ts`.
5. **Items:** all 38 icons resolve.
   - **TMs are not items.** They have no item id, and `@pkmn/img` has no TM-by-type disc. The plan's "TM discs by type" is class C or a CSS mark, not class A (see D71).
6. **Trainer sprites: 0 of 8 gym leaders.** The names are original, so `getAvatar` 404s for all of them.
   - Either map each leader to an existing Showdown trainer sprite, or treat leaders as class C.
   - The player marker can use a stock trainer sprite. The spike uses `trainers/lucas.png`.

## 2. Native resolutions and the scaling rule

**One art pixel is 2 CSS px, everywhere.** On a 3x phone that is 6 device px, on a
2x laptop 4 and on a 1x desktop 2: all whole numbers. gen5 sprites at 96x96 on the
same grid are 192 CSS px. The spike shows two of them fit a 390-wide stage with
both HP boxes, in the GBA arrangement.

| Asset | Native px | CSS px | Why this size |
|---|---|---|---|
| Battle backdrop | **216 x 170** | 432 x 340 | Covers frames up to 432 wide (the 430 Pro Max) at 340 tall, the stage the spike settled on. Center-cropped on narrower frames, so art keeps its focus in the middle 195. |
| Map backdrop | **216 x 432** | 432 x 864 | Covers the map area of every phone up to 430x932 (430 x 844 of map) and the desktop frame. Anchored to the bottom, where the entrance is. |
| Node icon | 16 x 16 | 32 x 32 | Inside a 44px circle. D61 asks whether this goes through `glyphNode` at the existing 8px grid instead. |
| Capability glyph | 8 x 8 | 16 x 16 | The existing glyph grid (D61). |
| Relic icon | 16 x 16 | 32, or 48 on a card at 3 CSS px | |
| Nav icon | 12 x 12 | 24 x 24 | |
| Currency icon | 8 x 8 | 16 x 16 | |
| Wordmark | 96 x 16 | 192 x 32 | |

**The scaling rule for fractional DPRs.** On a 2.625 Android or a 125% desktop zoom,
2 CSS px is not a whole number of device pixels, so art shimmers. The rule:

- Take `k = round(2 × devicePixelRatio)` device pixels per art pixel.
- Set one custom property `--art-px: calc(k / dpr × 1px)` at load.
- Recompute it on a `resolution` media-query change.
- Size every class C image as native × `--art-px`, with `image-rendering: pixelated`.

At DPR 1, 2 and 3 this is exactly 2 CSS px. That is one custom property and one listener, and it belongs in 5.0/1's tokens.

## 3. Map fit

**Yes at 390x844, with room.** The longest segment the tuning can draw is 7 steps
(`stepsPerSegment` segments 5 to 7, `{ min: 6, max: 7 }`) with up to 3 nodes each
(`nodeChoiceCount`). With the entrance and the gym that makes 9 rows. The synthetic
worst case, all 7 steps at 3 nodes, measured:

| Viewport | Row pitch | Node footprint | Tap target | Overlaps | Scroll |
|---|---|---|---|---|---|
| 390 x 844 | 84 px | 52 x 60 | 52 x 60 | 0 | none |
| 430 x 932 | 95 px | 52 x 60 | 52 x 60 | 0 | none |
| 1366 x 768 (desktop frame) | 71 px | 52 x 60 | 52 x 60 | 0 | none |
| 375 x 667 (SE, not a plan size) | 62 px | 52 x 60 | 52 x 60 | **7** | none |

**What gives.** The footprint the spike draws is mark plus tier pips plus the capability chip. That footprint fits.

- **What does not fit is today's current-step card.** It also carries the exact coin payout and the AI tier label, and it shows the reward-tier pips on a fight. That is D63.
  - At 84px pitch there is room for one extra short line under a node (about 14px), and not two.
  - At the desktop's 71px pitch there is room for none: 60 + 14 = 74.
- So the node on the graph can carry **one** of those facts at rest. The rest go to inspect, which needs D63's table amendment.
  - The alternative is a map that reveals those facts on the next step only, since only that row is a decision. The rows above it have room to shrink.
- **Below 390x844** (an SE), the worst case collides. The fix is a pitch floor: past it, the later rows compress to marks without pips. That is a ruling for 5.0/4, not a problem at the plan's sizes.

**Current commit behaviour**, recorded for 5.0/4: a single tap on a current-step node commits at once. There is no confirm step (`nodePick.submit`, `ui/app.ts:1236`).

**Four traps for 5.0/1:**

1. **Unconditional CSS is Detailed, not Pocket.** A root with no `data-density` attribute is styled as Detailed. Deleting the attribute without promoting the 108 Pocket rules to unconditional, and dropping the 13 others, silently ships Detailed.
2. **The test tooling defaults to Detailed** (`openApp`, `notFirstLaunch`, `TUTORIAL_SKIPPED_SETTINGS`), while the app defaults to Pocket.
   - The smoke run, `heights.json`'s top level and the v0-v3 gates all measure the mode being deleted.
   - Every one of those baselines moves in 5.0/1.
3. **A selector bug at `styles.css:1534`.** A comment sits inside the selector, so the `.pre-gym__choose` reset applies in Pocket only. It becomes correct by accident once Pocket is unconditional.
4. **Exposure counting (D43) counts only glyphs Pocket paints.** It is the one piece of persisted player state coupled to the mode.

Not a trap: the setting never reaches `core/` or the run log. `density.test.ts` asserts a byte-identical log across modes and bans the names from `core/`.
