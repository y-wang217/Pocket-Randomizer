## The finding that shapes the tier

**M7.1's done-when cannot be met by a session.** *"Every register row has an
observed or not-observed entry with a date"* needs six or more people playing
the game. A session can write the protocol and build whatever the protocol
needs to measure. It cannot run the rounds. Every item before this one was
closed by the session that built it. This one is closed by you, after two
rounds with testers. That is **D46**.

**Four of the fifteen register rows need a count nobody can take by watching.**
The tree cannot take it either:

- R2's first clause: *"open inspect on category more than twice in run two"*.
  Nothing counts inspect opens. `ui/tooltips.ts`'s `open()` has no hook and
  nothing records it.
- R2's second clause: *"Special-move-on-high-Atk picks do not fall between run
  one and run three"*. The decisions are logged, but **the log is deleted when
  the run ends** (`ui/app.ts:1433`, `clearRunLog()` on the summary), and
  `Copy result` shares the score, not the decisions. After a tester's run one,
  nothing is left to compare against run three.
- R7: *"inspect rate on a family has not fallen by run three"*. This needs the
  same count as R2, per family and per run.
- Move chips: *"testers expand every chip to a full card"*. You can see this
  by watching, but not reliably on a phone held by someone else.

That is **D47**. It recommends a fifth item, **M7.0**, a local playtest
recorder behind a URL flag, built before the protocol is written, the same way
D30 and D44 built their instruments before the items that needed them.

## What a tester's device has to be

- **A clean origin.** Exposure counts, coach marks, the intro and density all
  persist in `localStorage`. `Replay tutorial` resets the coach marks
  (`ui/app.ts:352`) and not the counts. **No control in the game resets
  exposure.** A tester on a device that has run GYMRUN before starts with no
  labels and is not a run-one tester for rows 1, 12 and 14. A private window
  works, and it keeps the store for the whole session, across runs.
- **A phone for at least one tester per round.** Row 7 is a touch disconfirmer,
  and the one row already in the playtest log came from an iPhone.
- **Run one's battle scrolls.** M6.1 measured the battle screen at **859px on a
  first run** against the 844 fold, because the labels on four move buttons
  wrap. That is recorded and not gated (D44), but a run-one tester on a 390x844
  phone meets it on their first fight, and the protocol should tell the
  observer rather than let it read as a finding.
- **Three runs per tester** for rows 1 and 14. A run ends at a loss as well as
  at gym eight. How long a new player's run takes has never been measured.
  Three of them is the largest time cost in the protocol, and round 1 should
  time it.

The playtest log's one row (2026-09-22, R5's mirror) counts for no register row
and should not be read as a round.

## The rows

Filed in [`../design/bible-discrepancies.md`](../design/bible-discrepancies.md)
with options:

- **D46.** M7.1's done-when needs testers, not a session. Recommendation: split
  it. **M7.1** is the protocol document, one session and one PR. **M7.1r1** and
  **M7.1r2** are the rounds, each closed by a docs PR of log rows. M6.4 is
  gated on M7.1r2.
- **D47.** Four rows need counts nothing takes. Recommendation: **M7.0**, a
  playtest recorder behind `?playtest=1`. It lives in `ui/` only. It counts
  inspect opens per family per run, keeps each finished run's decision log
  instead of discarding it, and exports both as one JSON download from the
  summary. It draws no RNG and touches nothing in `core/`, and it reshapes no
  logged decision, so no version axis moves. The flag keeps the export off the
  player's face. Built before M7.1, so the protocol can name the file a round
  collects.
- **D48.** Rows 9 and 15 are not tester observations. Recommendation: the
  protocol marks them *measured, not observed*, names the instrument, and the
  log records a dated entry with tester count 0.
- **D49.** "Decision surface" is undefined and the census cannot attribute
  words to rows. Recommendation: one instrument commit before M7.2's census
  that tags each counted word with the section 4 row it falls under, or with
  `unbudgeted`. Then define decision surface as every census surface except
  summary and log-sheet.
- **D50.** The baseline's instrument differs. Recommendation: M7.2 reports
  both deltas. One is against the committed Tier 0 table, as the item asks.
  The other is against the Tier 0 tree re-counted with today's instrument,
  wherever that tree can still render the surface. A surface it cannot render
  says so.
