## The method is unchanged and still working

Never build around a bible conflict. File it as a row in
[`../design/bible-discrepancies.md`](../design/bible-discrepancies.md) with the
section, the line, the options and a recommendation, and let the item wait.
**Seventeen rows, sixteen ruled.**

Tier 2 added four. Two are worth reading before Tier 3 because their reasoning
generalises:

- **D16** — Pocket was reaching its word count by *hiding* four facts rather
  than re-encoding them, which is C2. The tell was that the `power:` inspect
  trigger sat on the element the rule hid, so there was no tap that reached it.
  **When a mode hides something, check whether the gesture that reveals it
  actually exists.**
- **D17B** — the census was counting a split number and the strip's glyphs as
  words. The first fix exempted all `aria-hidden` text, which measured as too
  broad: it silently stopped counting the corner stamp's seed string. **A
  measuring instrument that flatters the item making the change is worse than
  an honest number.** One selector with a reason beside it instead.

## What Tier 3 walks into

**M3.2 asks for "four move chips per row" and M2.3 just built the chip.**
`moveChip` in `ui/scene.ts` takes `{ id?, name, type, category, basePower }`
and returns a `<button>`. It is the compact form of the same face — same
`typeChip`, same `categoryChip`, same `movePower` — so mounting it in the party
row is the intended reuse, not a new component.

**The party row is the largest component left**: 481 words in Detailed and
**121 in Pocket**, against a budget of 0. It is M3.2's whole job, and the drawer
(83) and pre-gym (39) surfaces are mostly it.

**Six stat glyphs are drawn and unmounted.** `stat-hp`, `stat-atk`, `stat-def`,
`stat-spa`, `stat-spd`, `stat-spe` are in M1.1's sheet and nothing renders them
yet. M3.2 is the item that does, through `glyphNode` — **the one renderer**, and
`test/glyphs.test.ts` asserts it is the sheet's only importer in the rendering
tree.

**The word/glyph pattern is established and should be followed, not reinvented.**
Pocket hides `.move__label` and `.chip__word` and shows the glyph; the other two
modes do the reverse. `HP`, `Lv` and `STAGES` are the same shape of problem on
the panel and the party row. Scope the rule **by component, not by surface** —
see the scoping trap below.

**D6 already ruled the priority chevron onto the Pokemon panel** (M3.1). The
mark exists: `movePriority` builds it from the sheet. M4.2 later asserts the
panel and the card share the token, so build it from `glyphNode` rather than
drawing one.

**`.chip--status` is already a census glyph slot**, so three-letter status chips
cost nothing. M3.1's "remove any status word" is about prose elsewhere on the
panel, not the chips.

## Four traps Tier 2 hit, none of which its own tests caught

Every one of these passed the component tests and was found by `npm run check`.
They are worth reading as a class: **the item tests prove the component, and the
gate proves the app is still usable through it.**

1. **Hover.** Making a card an inspect trigger turned a chip-sized hover target
   into a card-sized one, so the panel opened whenever the cursor crossed a card
   and then covered it. If you give something large a `data-tip`, give it
   `data-tip-hover="off"` as well.
2. **Scoping.** The density rule was written `.move .chip--type > .glyph`, on
   the reasoning that the item owned the move card and should not reach past it.
   That left every type chip on every *other* surface rendering the glyph **and**
   the word — R3, twice over — and surfaced as a 2.72px fold failure two screens
   away. **A component's encoding is scoped by component. A screen does not get
   to decide how an attribute is drawn; that is R1.**
3. **The walkers.** M2.3 put a confirm between tapping a move and committing it,
   and both app-walking bots clicked through and moved on. The band is
   `aria-modal` with a scrim, so that is a stuck walk, not a slow one. **If an
   item changes an interaction, `scripts/smoke.mjs` and
   `scripts/visual/browser.mjs` both model that interaction.**
4. **Screens drawing their own fields.** Three screens bypassed the move card
   component, two by assigning over `.move__pp.textContent` after the component
   built it — survivable when PP was one text node, silently destructive once it
   was four spans. `docs/design/inventory.md` finds these; §5 calls them the
   defect it exists to prevent.

## Conventions worth keeping

- **`contentHash` discipline.** Still `d4e080`. The whole tier touched no file
  under `src/core/`, which is what the standing gate wants and is easier than it
  sounds — the move face is presentation and the projection already carried
  every fact it needed.
- **A test whose premise the design changed gets updated, not weakened.** Nine
  of them this tier. The one to imitate is `summary.test.ts`: it counted every
  fact against the strip, and rather than lowering the number to match, it now
  counts strip facts against the strip **and** the two that moved against the
  slots they moved to. Lowering it would have made the test agree with a card
  that had lost two facts.
- **Deviations go in `docs/generation.md`, never into the prompt.** Sections 53
  to 56 are this tier's.
- **Generated files are generated.** `npm run census` and `npm run copy-audit`
  after any copy or face change. The `census` leg of `npm run check` prints a
  delta but **does not write** the file.
- **Commit at each checkpoint; only gated work reaches the trunk.** Three gate
  attempts went red before Tier 2's green one. Each red was a real defect.

## Two things nobody owns

**WebKit has never run.** `test:webkit` reports `SKIPPED — no browser binary` on
every gate across all of 4.10, Tiers 0 and 1 included. The engine axis exists
because two defects lived in exactly that blind spot, and Tier 2 rewrote every
move surface in the game. `npx playwright install webkit`, then
`npm run test:webkit`. **This is the single most likely place an unfound defect
is sitting.**

**The status readout is behind the long press, which is the weaker option.**
D17A ruled it there and it is inside the bible — R6 permits a secondary fact
behind a tap, and the panel prints it word for word. But R12 would rather the
concept were restructured than the sentence written, and the readout is
structured data (`MoveEffectFields`), not prose, so it is genuinely encodable as
glyphs. Worth an item before M7.2 re-censuses, or it stays a known concession.
